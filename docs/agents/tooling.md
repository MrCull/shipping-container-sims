# Agent tooling and browser smoke tests

Reference for `AGENTS.md`: reach for it when you run the smoke suite, work in a cloud session, take screenshots, record media, brief an implementer in a worktree, or benchmark Terminal Twin frame rate.

## Browser smoke tests

- **Browser smoke tests** (`pnpm run test:smoke`, Playwright, `src/**/*.smoke.ts`) are not part of `verify`. Run them alone with `scripts/bg.sh run --heavy pnpm run test:smoke <files> --trace off` (a second heavy job or a file edit during the run makes failures); every run ends with one `SMOKE: <n> passed, <n> failed, ...` line (`scripts/smoke-summary-reporter.mjs`), which is the result to report: a pipe (`| tail`) hides the exit code. CI runs them from the Actions tab ("Run workflow") or while a PR carries the `smoke` label, and they should be green before merging UI changes. Specs titled `@load` need a real frame rate and never run in CI. Frame assertions are ratios over a minimum wall-clock window (`tests/browser/frameSampling.ts`), never absolute counts. The `dev` project needs the dev API (`window.__tt`, `?viewer=`) and runs against one of two servers (`scripts/smoke-server.mjs`, `node --test scripts/test-smoke-server.mjs`): locally the Vite dev server by default (no build step, best for a spec or two); with `SMOKE_SERVER=build` (the default when `CI` is set) the smoke build, a bundled `vite build --mode smoke` into `.smoke-build/` (`SMOKE_BUILD_DIR`) that keeps the dev API, served by `vite preview` (page open to `__tt` ready is faster, so prefer it for long local runs; `pnpm run build:smoke` builds it and `SMOKE_BUILD_PREBUILT=1` serves it without rebuilding, as CI does). Code gated on the dev API checks `import.meta.env.DEV || import.meta.env.MODE === 'smoke'`, which folds to false in a production build; specs that read `process.env.SMOKE_SERVER` (set by the config) can tell the two servers apart (`build-stamp.smoke.ts`). The `prod` project (`*.prod.smoke.ts`) uses a production build. Each run picks free ports unless `SMOKE_DEV_PORT` / `SMOKE_PROD_PORT` pin them. In CI (`CI` set) a failing test is retried once (a pass on retry is reported as flaky) and the run stops after 5 failures; local runs have no retries and no cap. Setting `SMOKE_JSONL_REPORT=<file>` appends one JSON line per finished test attempt (`scripts/smoke-jsonl-reporter.mjs`, `node --test scripts/test-smoke-jsonl-reporter.mjs`), so a cancelled or timed-out run keeps its timings (CI sets it, one file per shard, and merges them); `SMOKE_JSON_REPORT=<file>` writes a Playwright JSON report, only when the run ends. `node scripts/smoke-timing.mjs <file>...` turns either (several files, one per shard, read together) into a duration-sorted Markdown table with a scene column, and flags every test over the 30 s budget (`--budget <s>`) in its row and in a `[!WARNING]` block, a warning that never fails the run (`node --test scripts/test-smoke-timing.mjs`).
- **Sharded CI smoke run** (`.github/workflows/pr-checks.yml`): `Smoke build` (job `smoke-build`) builds `.smoke-build/` (`pnpm run build:smoke`) and `.smoke-dist/` (production) once, counts the tests (`playwright test --list --grep-invert @load`) and uploads both bundles as the `smoke-bundles` artifact. Six `Browser smoke tests (shard i/6)` jobs (`smoke-shard`, `fail-fast: false`) download it and run `pnpm run test:smoke --grep-invert @load --shard=i/6` with `SMOKE_BUILD_PREBUILT=1` and `SMOKE_PROD_PREBUILT=1` (`SMOKE_PROD_DIR`, default `.smoke-dist`; `scripts/smoke-server.mjs`), so no shard builds; each uploads its JSONL as `smoke-report-shard-i`. `playwright.config.ts` sets `fullyParallel: true`, so a shard is a set of tests, not files (by file, three shards once took 7, 9 and 19 min); specs must not share state between tests (no serial describe, no page kept across tests), and local runs stay on one worker. The `Browser smoke tests (Terminal Twin)` job (`smoke`) runs `node scripts/smoke-merge.mjs <shard.jsonl>... --expect <count> --summary "$GITHUB_STEP_SUMMARY"`: one `SMOKE:` line, one timing table with the 30 s flags, and exit 1 when a test failed, fewer tests were reported than counted (a shard cancelled or timed out), or a test ran in two shards (`node --test scripts/test-smoke-merge.mjs`); it also fails when a shard job failed outside its tests. Check shard balance with `--shard=i/6 --list`.
- **Dispatch from the CLI:** `gh workflow run pr-checks.yml --ref <branch>` starts the sharded smoke run in CI (the Actions tab "Run workflow" does the same); `gh run watch` follows it. Use it to see whether a failure is specific to this machine before bisecting.

## Tooling

- **Cloud sessions:** a SessionStart hook (`.claude/hooks/session-start.sh`) runs `pnpm install` and sets `core.hooksPath` to `.githooks` (its `commit-msg` rejects a `Co-Authored-By` trailer); it does nothing locally.
- **Blender in cloud sessions:** opt-in `scripts/install-bpy.sh` (once; idempotent) installs the pinned `bpy` into `$HOME/.cache/tt-bpy-venv` and prints its python path for `pnpm run tt:assets --python <path>`; the session-start hook does not. Details: Terminal Twin `docs/assets-pipeline.md`.
- **Visual checks:** `pnpm run screenshot --path /sim/<sim-id> --wait 8000` saves a PNG to `.screenshots/` and reports page errors (headless Chromium, software WebGL, so no real frame rates). Options: header of `scripts/screenshot.mjs` (`--wait-for-fn`, `--scale`). Terminal Twin close-up: place the camera with `__tt.setCameraPose(...)` in `--eval` and add `--wait-for-fn "__tt.heroSettled() && __tt.perf().stats.heroFaces > 0"` (hero detail takes about a minute here).
- **README media:** `pnpm run capture-readme-media` (after `pnpm run build && pnpm run preview`).
- **Implementer worktrees:** the brief's first step is `scripts/worktree-base.sh <integration-branch>`, which puts the worktree on the integration tip or refuses with a one-line reason (`scripts/test-worktree-base.sh` tests it). Workflow: `docs/agents/implementing.md`. `scripts/merge-ticket.sh` sets the ticket's `handover.md` row after a green merge (`scripts/test-merge-ticket.sh`); `scripts/bg.sh` runs a long command detached and waits on its `EXIT` line (`run --heavy` takes the one machine-wide heavy lock, so peak-day runs and the smoke suite queue instead of overlapping) (`scripts/test-bg.sh`); `scripts/proof-runner.sh` runs several `tt:run` variants in parallel under the heavy lock and prints one table (`scripts/test-proof-runner.sh`); `scripts/timebox.sh` sets and reads an agent's wall-clock budget (`scripts/test-timebox.sh`); `scripts/remove-worktree.sh` removes a finished agent's worktree, locked or not, and refuses one in use (`scripts/test-remove-worktree.sh`).
- **Frame-rate benchmark:** `scripts/bench-preflight.sh` (quiet-machine check), `pnpm run build` then the `preview` entry of `.claude/launch.json` (port 4173), then the Benchmark button; `pnpm run tt:frame-report <file.json> [--record]` reads the JSON. Procedure: Terminal Twin `docs/optimising/frame-rate.md`.
- **Windows (Git Bash):** without `flock`, `scripts/bg.sh run --heavy` takes an mkdir lock directory (`bg-heavy.d` in the git common dir, holding the owner pid, a dead owner counts as free), so heavy jobs still queue and `scripts/bench-preflight.sh` still answers.
- **Laptop-only work** (needs a real GPU or the owner's eye): `gh issue list --label needs-gpu`. Cloud sessions and CI have software WebGL only.
